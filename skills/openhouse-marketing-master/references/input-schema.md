# 案件情報の整理

案件ごとに一つのJSONを作り、すべての媒体が同じ情報を参照する。値が不明な項目は空文字または空配列にし、仮の値を入れない。

```json
{
  "案件ID": "2026-001",
  "会社名": "",
  "イベント名": "完成見学会",
  "開催日": "",
  "開催時間": "",
  "開催場所": "市区町村まで",
  "住所公開範囲": "予約者のみに詳細案内",
  "予約方法": "",
  "予約URL": "",
  "電話番号": "",
  "掲載開始日": "",
  "掲載終了日": "",
  "想定来場者": "",
  "検討段階": "情報収集初期|土地探し中|会社比較中|間取り検討中|最終検討中",
  "描きたい暮らし": [],
  "希望トーン": "上品であたたかい|ロマンティック|自然体|洗練|その他",
  "避けたい印象": [],
  "物語の核": {
    "主役となる場面": "",
    "タイトル": "",
    "キャッチコピー": "",
    "基本ストーリー文": "",
    "根拠となる写真ID": [],
    "読後に残したい暮らしの価値": ""
  },
  "確認済み特徴": [],
  "承認済み性能": [],
  "来場特典": {"内容": "", "対象": "", "条件": "", "期限": "", "数量制限": ""},
  "施主許諾": {"写真使用": false, "外観公開": false, "間取り公開": false, "氏名公開": false},
  "写真観察": []
}
```

## 運用ルール

- 日付・時間・場所・予約方法・会社名は全媒体で完全一致させる。
- 性能表現は `company-profile.yaml` の承認済み表記と案件の根拠が両方そろった場合だけ使う。
- 施主許諾が `false` の対象は公開しない。
- 掲載終了日は原則として開催終了日以前または直後に設定する。
- 公開用原稿に空欄や「要確認」を残さない。未確認項目を使わず成立させるか、確認を求める。
- `描きたい暮らし` が空欄なら、写真から確認できる特徴と想定来場者を足場に、家族の時間、くつろぎ、季節、食卓など複数の情景を内部で検討する。
- タイトル案が選ばれたら `物語の核` を確定し、全媒体が同じ項目を参照する。媒体ごとに文章は調整してよいが、主役となる場面、写真上の根拠、暮らしの価値は変えない。
